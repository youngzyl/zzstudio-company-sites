What we build

Three layers, one working system.

Most AI pilots fail at the seams — retrieval that ignores permissions, an agent with no memory, prompts nobody can version. We build the three layers together, or just the one you’re missing.

01

Hybrid Context Search Vault

An enterprise retrieval layer that treats your knowledge as a governed asset. Lexical and dense search run side by side, results are fused and reranked, and every answer arrives with citations and the access rules already applied. Connect wikis, tickets, drive folders, code and databases over connectors you control.

  • hybrid retrieval
  • citations
  • ACL-aware
  • audit log
  • Ingestion pipelines that keep sources fresh and de-duplicated.
  • Retrieval API your own apps, IDE and chat surfaces can call.
  • Evaluation set built from your real questions, not a demo.

02

Personal AI Agent

A private agent that works for one person — with durable memory of their projects, preferences and past decisions. It reads from the vault, calls your tools, drafts, files and follows up, and asks before it does anything irreversible. Each person gets their own agent, not a shared inbox bot.

  • durable memory
  • tool use
  • approval gates
  • per-user scope
  • Memory design — what is remembered, for how long, and how it’s forgotten.
  • Tool integrations with least-privilege credentials you can revoke.
  • Traces and replay so anyone can see why the agent did what it did.

03

Skill Management

The layer that stops quality from drifting. Skills — reusable instructions, tools and checks — are written down, versioned, reviewed and measured like software. You get a registry, a test harness and a release process, so a good prompt becomes a maintained asset instead of a screenshot in a chat log.

  • versioned skills
  • eval harness
  • review workflow
  • rollback
  • Skill registry with owners, versions and deprecation dates.
  • Regression evals that run on every change, like CI for behaviour.
  • Authoring enablement so your team writes the next one without us.

How an engagement runs

Four steps, no black box.

We work in short, decision-shaped phases. Each one ends with something you can run, measure and keep — or a clear reason to stop.

01 / diagnose

Find the real constraint

Two weeks with your data and your people. We map sources, permissions and the questions that actually go unanswered, then write down what “working” will mean.

02 / prove

Prove it on 200 real questions

A thin vertical slice over your live corpus, scored against a golden set. You see retrieval quality and failure modes before committing to a build.

03 / build

Build it with your engineers

Paired delivery in your repo and your cloud. Weekly demos, reviewable commits, infrastructure as code, and no hidden services on our side.

04 / handover

Leave you able to run it

Eval harness wired into CI, runbooks, cost model, and a trained owner. Optional retainer for the quarter after launch, then you’re independent.
