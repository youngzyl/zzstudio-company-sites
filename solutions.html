01 — Retrieval

Hybrid Context Search Vault

A governed retrieval layer over everything your organisation knows. It answers with evidence, respects who is asking, and stays useful when the corpus grows past the point where anyone can hold it in their head.

Scope a vault for your corpus

Why hybrid, and not just vectors

Embeddings are excellent at meaning and terrible at precision. Your organisation is full of strings that must match exactly: part numbers, ticket IDs, error codes, contract clauses, internal acronyms. Running lexical and dense retrieval in parallel — then fusing and reranking — is the difference between “roughly related” and “this exact paragraph, in this exact revision”.

Retrieval modes we combine
ModeStrong atBlind spot
Lexical (BM25)Exact identifiers, names, code, quoted phrasesParaphrase and synonymy
Dense (vectors)Meaning across wording differencesRare tokens, numbers, precision
Metadata & filtersRecency, owner, source, classificationNeeds disciplined ingestion
Fusion + rerankOrdering the shortlist correctlyCosts latency — we tune the budget

What you get

  • Ingestion pipeline — connectors for wikis, drives, ticketing, chat, code and databases, with de-duplication, versioning and incremental sync.
  • Permission mapping — source ACLs carried through to retrieval, so an answer never leaks a document the asker can’t open.
  • Retrieval API — a documented endpoint with filters, citations and scores, consumable by your apps, IDE, chat surfaces or agents.
  • Evaluation harness — a golden set built from your real questions, scoring recall, precision and citation accuracy on every change.
  • Operations runbook — refresh schedule, embedding model upgrade path, cost model and failure playbooks.

Typical shape

4–10 weeks from kickoff to a production vault over one to three source systems. Storage and vector index run in your own cloud account; the embedding and reranking models are swappable, including fully local ones for air-gapped sites.

02 — Action

Personal AI Agent

One agent per person, with a memory of their work. It knows their projects, the decisions already made, the tone they write in and the tools they live in — then it drafts, files, schedules and follows up. It asks before anything irreversible.

Design an agent for your team

Memory is a design decision, not a feature

Unbounded memory turns into noise, cost and stale assumptions. We define what is remembered at three horizons — the working session, the project, and the durable profile — along with what expires, what is corrected by the user, and what is never stored at all. Every retrieval the agent performs is traceable back to a source or a stated preference.

What you get

  • Agent architecture — planner, memory store, tool router and approval gates, documented as an explicit state machine rather than prompt spaghetti.
  • Tool integrations — your ticketing, mail, calendar, drive, CRM or internal APIs, each with least-privilege credentials and per-user scoping.
  • Human-in-the-loop controls — read-only by default, confirm-before-write for consequential actions, hard limits on spend and blast radius.
  • Trace and replay — every run recorded with inputs, retrieved context, tool calls and outcome, so a surprising action can be explained after the fact.
  • Operator console — pause an agent, revoke a tool, inspect a memory, roll back a behaviour.

Guardrails we install by default

  • Allow-listed tools with explicit scopes; no ambient credentials.
  • Injection defences on retrieved content before it reaches the model.
  • Confirmation prompts for send, delete, pay, publish and merge.
  • Per-user data isolation, with audit logs retained to your policy.

03 — Quality

Skill Management

Skills are the unit of know-how: a reusable instruction set, the tools it may use, the examples that define good output, and the checks that catch bad output. We treat them like software — written down, reviewed, versioned, tested and retired.

Build a skill practice

The problem this solves

Without a skill layer, quality lives in someone’s chat history. A new model version silently degrades an output nobody wrote a test for. Two teams solve the same problem twice. Nobody knows which prompt is still trustworthy. Skill management replaces that with a registry, an owner per skill, and a test that runs on every change.

What you get

  • Skill registry — name, owner, purpose, version, dependencies, evaluation status and deprecation date for every skill.
  • Authoring standard — a house format for instructions, examples, tools, edge cases and refusal behaviour.
  • Evaluation harness — regression suites per skill, scored on every change, wired into your CI so behaviour is reviewed like code.
  • Release workflow — propose, review, canary, promote, roll back. With the audit trail your compliance team will ask for.
  • Model-swap readiness — the same suite run against a new model to answer “is upgrading safe?” with data.

Teach, then leave

We run authoring workshops with the people who own the work — support leads, legal, finance, engineering — so the second hundred skills are written by your team. Our measure of success is that you stop needing us for this.

Four ways to work with us.

Most teams start with a diagnostic, then decide. There is no obligation to continue, and no proprietary component that keeps you tied to us afterwards.

Diagnostic 2 weeks You have a corpus and a hunch, but no evidence yet. Retrieved evidence over your live data, a feasibility read, a scoped plan and a cost estimate.

Data stays in your account. Least-privilege credentials, encrypted at rest and in transit, source-level permission mapping, and retention rules you define. We sign NDAs and DPAs before the first dataset moves.

Sovereign & air-gapped

Honest measurement

We report retrieval quality and failure modes the same way we report wins. If the numbers say the project should stop, you will hear that in week two rather than in month six.
